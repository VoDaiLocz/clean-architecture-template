# UX Specification

## UX Principles

- The learner always knows what to do next.
- The learner sees progress and blockers in plain language.
- The learner never sees raw source/import/admin terminology.
- The UI supports repeated daily use, not marketing-page browsing.
- Desktop and mobile web must both be usable.

## Learner Screens

### Today Screen

Purpose: primary daily entry point.

Must show:

- next activity
- current unit
- unlock progress
- review blockers
- daily target
- weakest skill/part

Primary action:

- start next activity

Empty state:

- if onboarding missing, show onboarding CTA
- if placement missing, show placement CTA

### Activity Screen

Must support:

- concept lesson
- guided example
- focus drill
- mini test
- mistake repair
- practice test

Must adapt UI based on activity type.

### Review Screen

Must show:

- learner answer
- correct answer
- explanation
- transcript or passage evidence when relevant
- repair action

### Seven Part Overview

Must show:

- progress per part
- locked/unlocked units
- required action to unlock
- eligible tests
- weakness tags

Must not show placeholder cards.

## Admin Screens

Admin screens are separate from learner screens.

Required:

- source inventory
- asset discovery
- extraction status
- draft review queue
- validation issue detail
- publish queue
- content coverage
